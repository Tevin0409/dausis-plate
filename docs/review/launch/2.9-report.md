## Design calls made in the build (for QA, and for Tevin where noted)
- **Menu button style.** The spec says white at 14 % opacity with a white ring, sitting on 2.8's teal band. That band isn't on `main` yet, and today's header is cream. So the button matches the table chip (white, sand border), and it should switch when 2.8's band lands. It sits on its own left-aligned row below 600 px.
- **"Sent … Staff have been told." only on the phone that tapped.** That phone remembers the call's time in sessionStorage for the tab. Any other open call reads "Someone at your table asked at …", including one made from the order page. If storage is blocked, the phone that tapped also sees "Someone at your table asked", which is still true.
- **Bill rows on two lines:** the code and name with the total on the right, then the time, status and Mark paid. "DP-0106 ·" is kept together so the dot never ends a line.
- **Request area screen-reader announcements:** `aria-live="polite"` with `aria-relevant="additions"`, so new requests are announced but age ticks are not. Errors use `role="alert"` on the menu and the order page.
- **Exits:** a strip leaves at `--dur-exit` (220 ms) even when it is still marked as just arrived. The pill keeps its last text while it fades out, so it doesn't vanish before the fade.
- **Dev-only quirk:** the `/t/<token>` route redirects to `localhost` (`new URL("/", request.url)`), so on 127.0.0.1 open `/` directly afterwards. This predates 2.9, but QA will meet it.

## Flags outside this slice (not changed)
- **Press feedback under reduced motion.** `globals.css` `.press:active { transform: none }` under reduced motion predates 2.9. The spec says press feedback stays. This is a global call for dev.designer or Tevin.
- **Tap highlight.** There is no global `-webkit-tap-highlight-color: transparent`, so phones flash on tap. This predates 2.9 and is a one-line global fix.
- **2.4 board header.** Its meta line can leave a "·" alone at the end of a line at some widths.
